# 要件定義書

簿記用語の単語帳アプリ「簿記単」の要件定義です。
現在の実装（`lib/`、対象バージョン 1.1.0+14）を正として、実装済みの要件だけを記載しています。
画面ごとの詳細は [画面定義書](screen-definitions.md)、内部構造は [詳細設計書](design/README.md) を参照してください。

## 1. 背景と目的

| 項目 | 内容 |
| --- | --- |
| 背景 | 簿記の学習中、参考書の索引に載っていない用語があり、ネット検索では情報が多すぎて目的の説明にたどり着きにくかった |
| 目的 | 簿記用語の「調べる → 覚える → 試す → 計画する」を 1 つのアプリで完結させる |
| 想定利用者 | 日商簿記 3 級・2 級の受験者（独学者を想定） |
| 利用環境 | Android スマートフォン（オフラインでも主要機能を使える） |

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 対象 | Android アプリ（Flutter）。同梱データ: 簿記用語 1,373 語（`assets/products.json`）、仕訳問題 270 問（`assets/siwake.json`） |
| 補助 | プライバシーポリシーと `app-ads.txt` を置く静的ページ（Web で公開。公開版リポジトリには含めない） |
| 対象外 | ユーザー登録・ログイン、サーバーへの学習データ保存、端末間の同期、課金 |
| 対象外（ビルドは可能） | iOS / Web 版の配信。iOS の AdMob 設定はテスト用 ID のまま、Web 版は広告と簿記ニュースが動かない（Web はスクリーンショットの撮影にだけ使っている） |
| 対象外（未同梱） | Windows / macOS / Linux 版。プラットフォームフォルダはリポジトリに含めていない（必要なら `flutter create --platforms=windows,macos,linux .` で再生成できる） |

## 3. 機能要件

ID の右端は、対応する画面 ID（[画面定義書](screen-definitions.md)）です。

### 3.1 単語を調べる

| ID | 要件 | 画面 |
| --- | --- | --- |
| FR-01 | 単語名または読みガナの部分一致（大文字小文字を区別しない）で単語を検索できる | SC-01 |
| FR-02 | 検索欄が空のときは、収録単語とカスタム単語から無作為に 15 件を表示する | SC-01 |
| FR-03 | 単語をタップすると説明を表示する。表示した単語は検索履歴に残る（新しい順に最大 15 件を表示） | SC-01, SC-03, SC-53 |
| FR-04 | 単語ごとにメモを書いて保存できる。メモを書いた単語は一覧で確認・削除できる | SC-04, SC-54 |
| FR-05 | 単語の説明を画像にして、OS の共有シートから共有できる | SC-03 |

### 3.2 単語を整理する

| ID | 要件 | 画面 |
| --- | --- | --- |
| FR-10 | マイリスト（単語のグループ）を作成・名前変更・削除・並び替えできる。リスト名は空白のみ不可、最大 30 文字、重複不可 | SC-10, SC-13 |
| FR-11 | 単語を長押しして、複数のマイリストと「保存単語一覧」へまとめて割り当てられる | SC-05, SC-06 |
| FR-12 | 単語を「単語チェック問題」に登録・解除できる | SC-05, SC-22 |
| FR-13 | 収録されていない単語を、単語・読みガナ・説明を入力して追加できる（収録単語・追加済みの単語と同じ名前は不可） | SC-55, SC-56 |
| FR-14 | 一覧の項目はスワイプで削除できる（保存単語・チェック問題の解除は確認ダイアログあり） | SC-11, SC-12, SC-22 |

### 3.3 実力を試す

| ID | 要件 | 画面 |
| --- | --- | --- |
| FR-20 | 単語の説明文から単語名を選ぶ 4 択テストを 10 問出題する。出題対象は収録単語 | SC-20 |
| FR-21 | チェック問題に登録した単語だけで 4 択テスト（最大 10 問）を出題する | SC-23 |
| FR-22 | 誤答した単語のミス回数を記録し、結果画面に表示する | SC-21 |
| FR-23 | 仕訳問題を出題範囲（簿記3級-商業簿記 / 簿記2級-商業簿記 / 簿記2級-工業簿記）から 10 問出題する。範囲は 1 つ以上選ぶ必要がある | SC-24, SC-25 |
| FR-24 | 仕訳問題は借方・貸方ごとに勘定科目と金額を入力し、科目と金額の組が順不同で完全一致したら正解とする | SC-25 |
| FR-25 | 勘定科目の選択肢は、正解の科目に全問題の科目から選んだ誤答候補を加えて最低 10 件にし、並べ替えて表示する（消去法・並び順で解けないようにする） | SC-25 |
| FR-26 | 金額欄から電卓を呼び出し、計算結果を入力できる。金額は 3 桁区切りで表示する | SC-25, SC-29 |
| FR-27 | 結果画面で問題ごとの正誤・正解仕訳・解説を確認し、個別の問題を解き直せる。全 270 問の一覧からも解ける | SC-26, SC-27, SC-28 |
| FR-28 | 再挑戦時にリワード広告を最後まで見ると、問題数が増える（単語テスト +10 問、仕訳問題 +5 問）。見なかった場合は同じ問題数で再挑戦する | SC-21, SC-26 |
| FR-29 | 仕訳問題の誤りを、問題 ID をコピーしたうえで Google フォームから報告できる | SC-25 |

## 4. 非機能要件

| 区分 | 要件 | 実現方法 |
| --- | --- | --- |
| 性能 | 起動時に UI を止めない | 単語 JSON（約 500KB）と仕訳 JSON（約 190KB）のパースを `compute()` で別 isolate に逃がす |
| 性能 | 検索入力で引っかからない | 入力を 250ms デバウンスしてから絞り込む |
| 可用性 | オフラインで主要機能を使える | 単語・問題データはアプリに同梱し、ユーザーデータは端末内（`shared_preferences`）に保存する。ニュースだけは通信が必要 |
| 信頼性 | 起動直後に操作しても保存済みデータを消さない | 永続化 Notifier の更新処理は、保存データの読み込み完了を待ってから行う |
| 信頼性 | 保存データが壊れていても起動できる | 壊れた JSON は読み飛ばし、空の状態で起動する |
| 品質 | 同梱データの誤りで正答が不正解にならない | 仕訳の貸借一致・ID と単語名の重複などをテストで検証する（[テスト報告書](test-report.md)） |
| プライバシー | 学習データを外部に送らない | メモ・マイリスト・スケジュール等は端末内のみに保存。外部送信は AdMob SDK によるもののみ |
| セキュリティ | 外部由来の URL で不正なページを開かない | WebView・RSS のリンクとサムネイルは `http` / `https` に限定。WebView からのカメラ・マイク・位置情報の要求は拒否 |
| 運用 | 収益用の広告 ID をリポジトリに置かない | 広告ユニット ID は `--dart-define-from-file`、アプリ ID は `android/admob.properties` で注入。未設定時は Google のテスト用 ID |
| 保守性 | UI とロジックを分ける | Riverpod の Provider / Notifier に状態と永続化を集約し、画面は表示と操作に専念する |
| 対応 OS | Android 7.0（API 24）以上 | `minSdk` は Flutter の既定値（24）、`targetSdk = 36` |

## 5. 制約・前提

- 単語・マイリスト・メモ・ミス回数は単語名で紐付けるため、単語名は収録単語とカスタム単語を通して一意とする。
- リリースビルドには Git 管理外の署名設定と広告 ID の設定ファイルが必要（[RELEASE.md](../RELEASE.md)）。
- 現在の実装の既知の課題（カスタム単語がテストに出題されない等）は [詳細設計書 1.10](design/01_architecture.md#110-既知の課題) に記載。
